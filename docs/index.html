Исходники Windows BLE-монитора и проверенные результаты измерений двух LiFePO₄ аккумуляторов в резервной системе PowMR. Данные обезличены.

Проект

ANENJI BMS Monitor (Windows) — открытые результаты экспериментов

Язык: English · Материалы: наблюдения пользователя, 6–12 ноября 2026 г.

Проект для чтения данных двух аккумуляторов ANENJI LiFePO₄ 12,8 В / 100 А·ч, оборудованных BLE BMS с рекламируемым именем SH12100-H-*. Рабочая проверка проведена на Windows с Python 3.13.17, Bleak 3.0.2 и aiobmsble 0.30.0. Программа показывает напряжение, ток, SOC, ячейки, температуру, флаги MOS, ошибки и записывает CSV на Рабочий стол.

Ограничение безопасности: проект предназначен только для наблюдения и анализа. Данные BLE могут быть ошибочными или недоступными. Не используйте программу для защиты батареи, автоматического управления зарядом, отключения при аварии или принятия решений, от которых зависит безопасность.

Быстрый запуск исходников

  1. На Windows установите Python (рекомендуется версия 3.13) и зависимости: py -m pip install -r requirements.txt.
  2. Создайте рядом с исходниками batteries.json по образцу batteries.example.json. Замените оба демонстрационных имени точными именами Ваших BMS; они должны совпадать с именами Bluetooth-рекламы.
  3. Запустите py battery_gui_v8_13.py. Нажмите «Обновить»; сканирование и чтение выполняются только по кнопке.
  4. Для EXE также установите PyInstaller: py -m pip install -r requirements-build.txt и запустите BUILD_ANENJI_BMS_v8_13.bat. Файл batteries.json должен лежать рядом с EXE при запуске.

Никаких персональных адресов Bluetooth, пользовательских путей Windows или журналов владельца проект не содержит. Готовый Windows EXE, собранный для конкретных аккумуляторов владельца, не публикуется.

Что было подтверждено

  • Обе BMS действительно передают BLE-объявления SH12100-H-*.
  • Для испытанных устройств GATT содержит FFFA (сервис), FFFB (передача запросов) и FFFC (уведомления); при успешном опросе известен ответ на read-only запрос A5 A5 00 03 ....
  • На Windows 12.11.2026 наблюдались Could not start notify on 0019: Unreachable и Characteristic fffc was not found!; в более поздних запусках чтение обеих батарей успешно и в варианте aiobmsble 8.12, и через прямой Bleak 8.13.
  • Причина временных сбоев не доказана, как и преимущество 8.13 по надёжности: при успешных тестах 8.13 дополнительный обход подписки не использовался.
  • В зарядных экспериментах с PowMR при установках Bulk 14,2 / 14,3 / 14,4 В, Float 13,7 В наблюдались завершения тока около 13,61 В, при этом SOC BMS мог быть 93%/90%, а дельта одной батареи достигала ~46–50 мВ. Значение 14,4 В — уставка, фактическое достижение его не зафиксировано. Реальная стадия Bulk/Float прибором не подтверждена.
  • При разряде дельта той же батареи могла снижаться до ~4–7 мВ; отдельная батарея имела ~5–10 мВ. Это не диагноз и не доказывает ни отказ балансира, ни корректность показаний SOC.

Установка

  • Инвертор: PowMR POW-HVM1K-12V, 12 В / около 1 кВт, при доступной сети — BYPASS.
  • АКБ: 2 × ANENJI LiFePO₄ 12,8 В 100 А·ч, параллельное подключение; каждая батарея имеет собственную BLE BMS.
  • Мониторинг: две BMS семейства SH12100-H-*, ток, напряжение, напряжения 4 ячеек, SOC, состояния MOS, температура, ошибка BMS, дельта.
  • Настройки теста инвертора: программа 26 (Bulk/CV) 14,2 → 14,3 → 14,4 В; программа 27 (Float) 13,7 В; BMS пишет Charge MOS=ON во всех приведённых ниже точках.

Интерпретация — что известно, а что нет

Подтверждено измерением: при повышении установки Bulk с 14,2 до 14,4 В наблюдаемое завершение заметного зарядного тока оставалось около 13,61 В. При разряде дисбаланс напряжений ячеек первой АКБ уменьшался. На момент наблюдений защита BMS не фиксировалась и Charge MOS был ON.

Не подтверждено: достижение реального напряжения 14,4 В, точный момент смены стадий Bulk/Absorption/Float, физическая остаточная ёмкость, истинная точность SOC, конкретные пороги балансира и наличие неисправности ячейки/балансира. Постоянное свечение CHG инвертора указывает на статус завершения заряда по его интерфейсу, но не измеряет фактическую ёмкость.

Инженерное замечание: ΔV — это измеренный разброс напряжений между ячейками в конкретный момент и при конкретном токе; не прямое измерение остаточной ёмкости и не основание для самостоятельного изменения параметров BMS. Сопоставлять нужно записи при близких токе, напряжении, температуре и SOC. Значения SOC двух BMS могут иметь разные погрешности.

Это описание единичного испытания, не инструкция назначать универсальные напряжения зарядки для других батарей.

Что было увидено в реальном GATT

На испытанных BLE-модулях обнаружены характеристики:

UUID Свойства, наблюдавшиеся в приложении Назначение в испытании
0000fffa-0000-1000-8000-00805f9b34fb сервис Контейнер для GATT-канала BMS
0000fffb-0000-1000-8000-00805f9b34fb READ, WRITE WITHOUT RESPONSE Запросы к BMS
0000fffc-0000-1000-8000-00805f9b34fb READ, NOTIFY Ответы и уведомления BMS

В успешных сеансах Windows Bleak видны GATT-хэндлы FFFB@0016 и FFFC@0019. Это примеры для двух экземпляров устройства, а не гарантированные хэндлы для всех версий BMS.

Read-only пакет, успешно получивший ответ в nRF Connect 8 ноября: A5 A5 00 03 00 00 00 48 44 2D. Он относится к запросам чтения; его не следует без анализа повторно использовать с иными устройствами. Ответ начинался с A5 A5 00 03 .... Используются реализованные в aiobmsble проверки и декодер.

Сбои и точные сообщения

  • BleakError: Could not start notify on 0019: Unreachable — обнаружение устройства прошло, но подписка на GATT-уведомления не открылась.
  • BleakCharacteristicNotFoundError: Characteristic fffc was not found! — нужная характеристика отсутствовала в доступном при данном подключении наборе сервисов.
  • WinError -2147023673: ошибка Windows с текстом об отмене операции; не доказательство, что человек действительно отменял операцию.

Нельзя по одному логу определить, что причина на стороне Windows, прошивки BMS, радиоусловий или конфликта соединений.

Чему научили успешные испытания

  • Вариант v8.12 через aiobmsble 12 ноября в 16:07 и 16:17 успешно прочитал обе BMS с первой попытки.
  • Вариант v8.13 через BleakClient с поиском GATT без использования кэша (winrt.use_cached_services=False) 12 ноября в 16:25 и 16:32 успешно прочитал обе BMS с первой попытки.
  • В обеих успешных попытках v8.13 подписка на FFFC сработала обычным способом. Запасной вариант прямого чтения FFFC не применялся и не был подтверждён испытаниями.
  • Следовательно, нельзя утверждать, что v8.13 устранил первопричину или доказанно надёжнее v8.12. Полезная особенность v8.13 — больше диагностики и три последовательных режима поиска сервисов (uncached, default, cached).

При переносе на другое оборудование

Запустите только один BLE-клиент за раз, укажите в локальном batteries.json точные Bluetooth-имена своих двух BMS, не подставляйте чужие MAC. Запросы только на чтение; изменения защит BMS экспериментальным ПО недопустимы. Не отправляйте в публичные issues реальные MAC-адреса, имя пользователя Windows или необработанные логи.
